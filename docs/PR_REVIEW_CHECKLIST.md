# PR レビューチェックリスト（Copilot 生成 PR 用）

このチェックリストは、GitHub Copilot やコーディングエージェントが作成した PR をレビューする際に使用します。

## 基本チェック

### コードの品質

- [ ] **コードが正しく動作する**
  - ビルドエラーがない
  - テストが全て通る
  - Lint エラーがない

- [ ] **変更が最小限である**
  - 必要な変更のみが含まれている
  - 不要なコードの追加や削除がない
  - フォーマット変更のみの行が混ざっていない

- [ ] **既存の動作を壊していない**
  - 既存のテストが通る
  - 既存機能に影響がない（または意図した影響のみ）

### ファイル操作

- [ ] **ファイル移動が適切**
  - `git mv` で履歴が保持されている
  - 移動先のパスが正しい
  - 移動後のインポートパスが更新されている

- [ ] **削除が適切**
  - 削除が必要なファイルのみが削除されている
  - 削除による影響が確認されている

- [ ] **追加が適切**
  - 新規ファイルの配置が適切
  - 命名規則に従っている

### 依存関係

- [ ] **依存関係の追加が適切**
  - 必要なパッケージのみが追加されている
  - バージョン指定が適切（catalog を使用）
  - セキュリティ上の問題がない

- [ ] **workspace の依存関係が正しい**
  - `workspace:*` が適切に使用されている
  - パッケージ間の循環参照がない

### 設定ファイル

- [ ] **package.json が正しい**
  - scripts が適切に設定されている
  - dependencies と devDependencies の分類が正しい
  - name, version などのメタ情報が正しい

- [ ] **tsconfig が適切**
  - コンパイラオプションが適切
  - paths などの設定が正しい
  - ベースとなる tsconfig.base.json を参照している

- [ ] **その他の設定ファイルが正しい**
  - `.gitignore` で不要なファイルが除外されている
  - `.env.example` が必要に応じて更新されている

## セキュリティチェック

- [ ] **機密情報が含まれていない**
  - `.env` ファイルがコミットされていない
  - API キー、パスワードなどが含まれていない
  - トークンや認証情報が含まれていない

- [ ] **依存関係に既知の脆弱性がない**
  - `pnpm audit` を実行して確認
  - 高リスクの脆弱性がある場合は対応

## モノレポ構成チェック

- [ ] **パッケージ構成が適切**
  - `packages/` 配下に適切に配置されている
  - パッケージ名が `@ts-sample/<name>` の形式

- [ ] **ワークスペース設定が正しい**
  - `pnpm-workspace.yaml` に追加されている
  - ルートの `package.json` の workspaces に含まれている

- [ ] **ビルド順序が正しい**
  - 依存関係に基づいたビルド順序になっている
  - `pnpm -r run build` で全てビルドできる

## CI/CD チェック

- [ ] **CI が通る**
  - GitHub Actions のワークフローが成功している
  - 全てのジョブが通っている

- [ ] **テストカバレッジが維持されている**
  - 新規コードにテストが含まれている
  - カバレッジが著しく低下していない

## ドキュメント

- [ ] **README が更新されている**
  - 新しいパッケージが追加された場合、README に記載
  - コマンドの変更がある場合、README を更新

- [ ] **コメントが適切**
  - 複雑なロジックにコメントがある
  - 既存のコメントスタイルに従っている
  - 不要なコメントアウトがない

## Prisma 関連（該当する場合）

- [ ] **スキーマが適切**
  - `schema.prisma` の構文が正しい
  - マイグレーションファイルが適切に生成されている

- [ ] **接続設定が正しい**
  - 環境変数から接続情報を取得している
  - `.env.example` に必要な変数が記載されている

- [ ] **マイグレーションが適用できる**
  - `pnpm --filter @ts-sample/prisma run migrate:dev` が成功する

## Copilot 特有のチェック

- [ ] **AI が意図を正しく理解している**
  - PR の目的が達成されている
  - 不要な変更が含まれていない

- [ ] **生成されたコードの品質**
  - コーディング規約に従っている
  - 可読性が高い
  - パフォーマンス上の問題がない

- [ ] **エッジケースの考慮**
  - エラーハンドリングが適切
  - null/undefined のチェックが適切

## コミット

- [ ] **コミットメッセージが適切**
  - 何をしたかが明確
  - 簡潔で分かりやすい

- [ ] **コミットが適切に分割されている**
  - 論理的な単位で分割されている
  - 大きすぎるコミットがない

## 総合判断

### 承認する場合

以下の条件を満たしている場合、PR を承認します：

- 全ての必須チェック項目が満たされている
- CI が通っている
- セキュリティ上の問題がない
- 既存機能を壊していない

### 修正を依頼する場合

以下の場合は修正を依頼します：

- 必須チェック項目が満たされていない
- セキュリティ上の問題がある
- 既存機能に意図しない影響がある
- コードの品質が著しく低い

### コメントのみの場合

以下の場合はコメントのみ残します：

- 軽微な改善提案
- 将来的な改善案
- 参考情報の提供

## レビューコメント例

### 良い例

```markdown
このファイル移動により、モノレポ構成が明確になりました。`git mv` で履歴も保持されています。

ただし、`packages/sample-new/README.md` に使用方法を追加すると、より分かりやすくなると思います。
```

### 改善が必要な例

```markdown
以下の点を修正してください：

1. `.env` ファイルがコミットされています。削除して `.env.example` のみにしてください。
2. `packages/sample-new/package.json` の `dependencies` に `typescript` が含まれていますが、これは `devDependencies` に移動すべきです。
3. テストが不足しています。少なくとも基本的なテストケースを追加してください。
```
